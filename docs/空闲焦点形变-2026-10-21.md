# 空闲时也跟随焦点形变（1.6.5.0，2026-10-21）

## 需求

以前只有**录音期间**胶囊才会因焦点在/不在输入框而在圆与椭圆之间切换；没录音时它是静态的，
必须说一句话才知道结果。要求：空闲时焦点变化也要有同样的形变动效（圆 ↔ 椭圆）。

## 现在的时间线

| 状态 | 焦点在可编辑输入框 | 焦点不在输入框 |
|---|---|---|
| 空闲（未录音） | 圆（麦克风） | 椭圆（右侧标签「缓存」） |
| 录音中 | 圆，边说边上屏 | 椭圆，右侧「监听中」，文字进缓存 |
| 有未上屏文字 | 椭圆（复制按钮，与焦点无关） | 椭圆（复制按钮） |

形变走的是同一条 `ShapeMotion` 弹簧曲线（果冻/回弹），不是瞬间跳变。截图为自检产物
`work/idle-focus-states.png`（左：圆；右：空闲椭圆，右半格写「缓存」）。

## 实现

- `MemoryPill` 增加空闲分支：录音中有 `delivery` 时按 `inputFocused`；否则未上屏缓存优先（保持复制态），
  再按 `!inputFocused && (idle || error)` 判椭圆。
- 新增 400ms 的 `focusWatch` 定时器（`WatchIdleFocus`）：只在 `idle`/`error` 且缓存为空时工作。
  先读 `GetForegroundWindow` + `GetGUIThreadInfo`（微秒级），**只有窗口/焦点这一对变化时才做 UIA 判定**，
  判定在工作线程上跑并有 400ms 熔断，避免拖住 UI。
- 焦点对判定一次要重试最多三次（`idleAttempts`）：UIA 的无障碍焦点比真实焦点晚一两帧，
  只信一次会出现「移回输入框却停在椭圆」的假结论。三次后锁定该结果，停止轮询。
- 空闲椭圆不是复制按钮：`ShortClick` 里没有缓存时点击一律开始录音，不会复制空内容；
  右侧文案走新的 `stashed` 分支写「缓存」，可读性上区分「复制」与「仅缓存」。
  长按仍然清空缓存并开始新一轮（缓存为空时等于直接开始）。
- 可访问性文案同步：空闲椭圆读作「当前焦点不能直接输入，文字会先缓存」，
  空闲圆读作「这里可以直接输入，点一下开始说话」。

## 验证

新增 `--idle-focus-test`（不需要麦克风/模型）：真实 WinForms 窗口 + 真实前台切换，断言

1. 焦点进文本框 → 形状回到圆，且 `shape.Settled`（证明是动画插值完成，不是直接赋值）；
2. 焦点移到只有按钮的窗口 → 形状变椭圆并稳定；
3. 焦点回文本框 → 再变回圆（覆盖上面那条 UIA 滞后重试）；
4. 有未上屏文字时，无论焦点在哪都保持复制椭圆，且可访问性名称含「复制」。

连续三次运行全部 PASS；同一份产物上 `--self-test`（新增空闲形状断言）、`--focus-test` 也全部 PASS。
