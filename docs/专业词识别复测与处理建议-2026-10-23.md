直接调用生产共享函数 `dictionary_rules.preview` 与 `hotwords.near_miss`，输出保存于 `work/term-diagnosis-20261023-text-probes.json`，关键输出有 assert 校验：

| 输入文本 | 当前替换结果 | 含义 |
|---|---|---|
| `coldex` | `coldex` | Codex 旧规则限定 `context: zh`，纯英文不替换 |

| 打开coldex | 打开Codex | 含中文时，同一错法能替换 |

前两项的热词门禁仍返回 Codex，但“触发救援”不等于“复解成功”：声学路径必须实际能解出目标词，且接受守卫通过。救援仅作用于定稿，草稿没有这一层。中文谐音不是现有英文拼写近似检测的能力范围。

`A P → API` 是当前磁盘已有规则；此前《词典词表体检与更新》曾明确排除它。本轮只报告差异，不回滚用户词典。旧报告中的“没有误伤”不能覆盖本次新增规则。

## 处理建议与验收

1. **Codex 先确认真实错法与场景。** 当前 `coldex/colex` 等规则已有，若实际是纯英文场景，语言限制可解释替换不生效。只在明确审查该词误伤后调整 Codex 的适用范围，不批量取消旧规则的 `context`。若实际输出是另一种拼写或中文谐音，先把真实错法与原音频固定下来。
2. **修规则要同时测反例。** `grid commit → git commit` 可以作为候选，但需检查普通英文/混说中的合法 grid 用法；`A P → API` 应先处理 APP 拆字的误改风险。`cash → cache`、`A → API` 不能全局替换。
3. **漏音和分段问题用同音频对照定位。** API 的整段结果与分段结果不同，宜对相同音频比较整段、分段、救援前后及草稿/定稿；词表不能恢复已经丢掉的任意音节，也不能修正文中所有中文误音。
4. **建立有覆盖的术语专项，再判断扩大词表或训练。** 先覆盖实际使用的软件名、缩写和专业词，分别含独念、中文句内和英文句内；制作错法的材料与验收材料分开，并加合法普通词、未说术语、否定和静音反例。旧 174 条不覆盖 Codex，不能替代专项；不以本次结果决定换模型。

本轮未构建、未改生产行为，未运行 175 秒协议长测、桌面 UI/送字或真实麦克风验收。先前无 Codex 固定音频；用户随后提供本人实录，后续证据如下。
