# VoxFix Desktop 1.6.36.0

完全本地的 Windows x64 语音输入。当前识别使用 **SenseVoiceSmall INT8**，配合 Silero VAD 分段和 CT-Transformer 标点，不调用云服务，不加载 Qwen 或润色大模型。1.6.29.0 起识别权重换成公开真人语料微调版；1.6.30.0 起支持个人词典（解码后词表），1.6.31.0 起支持解码期热词偏置（救援通道）；1.6.32.0 取消 Ctrl+C 接管，复制未上屏缓存只能点胶囊右侧按钮；1.6.33.0 修好右键菜单不关闭的问题（点任意处、选任一项、Esc、收起、退出都会关掉菜单）；1.6.34.0 把词典做成右键「词典」里的编辑器，并按辅音骨架认近音（`Jason` 也会改成 `JSON`）；1.6.35.0 菜单项文案改为「词典」（原为「词典…」）；1.6.36.0 右键菜单改为白色卡片，收起 / 词典 / 退出各带一个图标，行宽随文字，不再留空白。

打开项目根目录的 `VoxFix Desktop.lnk`，或 `bin/VoxFix Desktop.exe`。保留项目目录结构、`.venv` 和现有 Python 环境。

## 使用

圆形、胶囊和形变中的外边缘按矢量路径四倍超采样绘制，再高质量缩回原有屏幕尺寸；图标与文字的中间图层同步提高绘制精度，避免边缘台阶及低分辨率图层重复缩放。

悬浮窗不再弹出额外小字提示，包括悬停说明、输入框恢复、复制结果和录音操作说明。窗口本身的状态文字、右键菜单和供屏幕阅读器读取的说明保留。

无输入焦点、麦克风关闭且没有缓存时，胶囊以单层深石墨灰底显示麦克风轮廓和“未开启”，不显示复制图标、内部圆底、分隔线或下划线；悬停轻微提亮，静止时无呼吸动画。已有缓存时仍显示复制状态。

圆形、胶囊和中间形状统一使用内嵌蓝紫暖粉底图、石墨表面、顶部柔光、细亮边与白色图标；底图固定在控件内部，形变只改变裁切外形，不依赖桌面壁纸，不包含桌面背景模糊。右键菜单沿用同一底图与材质。按下时材质和内容整体微缩，焦点形变沿用可打断的等面积弹簧；无缓存的空闲形变始终保留同一个麦克风，随外形连续移动缩放；有缓存的复制内容再做淡入切换，避免图标重影。监听恢复持续向外扩散的双层波环，开关与收尾保持波环相位，声纹只随实际讲话变化，保留转写进度线；关闭系统动画时这些反馈静态显示。未开启、监听中、转写中、复制和已复制的可见笔画统一居中，不随文字长度与复制过渡上下偏移。

点击须在本窗口按下并在可见外形内松开才执行；拖动、移出窗口或失去鼠标捕获取消本次点击与长按，移回后须重新按下。收起会清除按压、悬停反馈和鼠标捕获，再次呼出不会沿用旧手势。

录音时滚动消息（上下或横向）不会暂停送字。焦点仍在输入框时继续输入；点击、拖选和实际焦点变化仍保留输入位置保护。

Win+H 呼出并录音，再按暂停语音但保留窗口，再按继续；只有 Esc 从键盘结束并收起。每次新会话成功开始时清空上一轮缓存，启动失败不清空。

**个人词典**：识别结果里的固定错法（例如说 GitHub 被写成 "get up"）可以在项目根目录 `dictionary.json` 里人工纠正。每条规则写"错法 → 正确写法"，草稿和定稿都会替换，保存后下一段语音即生效，无需重启：

**右键「词典」**：不用手改 JSON。菜单里点「词典」打开编辑器——左边选一个词，右边每行写一种被听错的写法，
添加/删除词，保存后下一句生效（窗口关掉时若有未保存修改会问一次）。编辑器把 `hotwords` 写成全部词、
把 `rules` 写成有错法的词（`context` 固定 `zh`），并且会重写整个文件。

```json
{
  "rules": [
    { "to": "GitHub", "from": ["get up", "git up", "git hub"], "context": "zh" }
  ]
}
```

- `context: "zh"` 表示只在中英文混说的句子里替换，纯英文句子保持原样（避免改坏 "I get up at seven" 这类正常英文）；删掉该字段则任何句子都替换。
- 替换发生在标点之前，只改写 `from` 列出的写法，不触碰其他内容；文件缺失或写错 JSON 时词典层自动停用，不影响识别。
- 词表按整词匹配，"get up" 不会误伤 "forget upper" 内部。

**热词偏置**：同一个文件里的 `hotwords` 是"解码期"词表，作用在识别本身，不是事后替换。
定稿文本里出现读音接近某个词的片段（`pyython`、`gitthub`、`J SON`）时，会用偏置解码把这段音频复解一次；
复解结果里出现的词表词更多才采用，否则原样保留。草稿不做这一步，所以屏幕上先看到的仍是普通识别结果。

```json
{
  "hotwords": ["GitHub", "Python", "API", "JSON", "PDF", "WiFi"],
  "rules": [
    { "to": "GitHub", "from": ["get up", "git up"], "context": "zh" }
  ]
}
```
（上面就是默认值：`hotwords` 默认这六个词，`rules` 默认只有 GitHub 一条。）

- **不写 `hotwords` 就不启用**：行为与 1.6.30.0 完全一致，没有额外开销，不会多占内存。
- 写入后第一次真正触发会多约 1 秒（加载第二个解码会话），之后每次约 35–60 毫秒；
  闲置三分钟自动释放那部分内存。没命中近音片段的句子完全不受影响。
- 能修的是"读起来像但写错"的情况（多字母、少字母、被空格拆开）；首个音节就听错的
  （例如 Kotlin 被听成 coattland）和解码期插不进 token 的词，这一版还救不回来。
- `rules` 那层事后替换照旧生效，两层并存：先偏置，再替换，最后加标点。
开始和收尾不会为了短暂的处理状态把胶囊缩成圆形或闪切成声纹；监听波环保持连续，准备期间不闪出复制图标。实际输入目标变化时仍正常切换圆形与胶囊，讲话时仍显示声纹。
收尾期间再按 Win+H，会保留一次重开请求，等尾字收齐后自动开始；Esc 取消该请求并收起。
悬浮窗显示且已定稿的缓存只能点胶囊右侧“复制/已复制”取走，按钮可重复点，复制结果不清空缓存。**Ctrl+C 不再被程序接管**：1.6.32.0 起无论是否有缓存都直接交给当前应用，复制只能靠手点按钮。
登录后台待命和撤销方法见[快捷键说明](WinH与Esc快捷键-2026-10-21.md)。

窗口直接呼出，没有淡入、上浮或缩放。有输入框首帧就是圆形，没有输入框才是椭圆；显示前完成工作线程焦点判定和新会话准备，不先画旧形状。
首次打开和再次呼出都会自动开始录音识别，不需要再点麦克风。冷启动先等待本地模型就绪；
通过 Win+H 呼出时按下即开始请求，不必松开 Win；录音中按 Win+H 则暂停并收齐尾字，窗口保留。
拖动后的位置保存在 `work/window-position.txt`；收起、退出重开都恢复该位置，显示器断开时回到可见范围。
右键“收起”会先结束当前录音并收齐尾字，再隐藏窗口，保留进程、模型和未上屏缓存。菜单本身点窗口外任意位置、选任一项、按 Esc 都会关闭，不会一直悬在桌面上。
再次运行程序或现有快捷方式即可原位呼回，不抢走输入焦点；Win+H 已由程序接管。

1. 有输入框时，先点输入位置，再点麦克风开始录音；识别草稿一有文字就送入原位置，不等停顿。后续结果变更时修订本轮已写入的当前段，停顿后按最终结果补齐文字和标点。修订只覆盖当前草稿，不修改用户原文或已完成段落；手动编辑、切换焦点或送字不完整后停止修订，并缓存剩余结果，下一段可在重新确认输入位置后继续。
2. 没有可确认的输入框也能录音。切换窗口或手动编辑后继续收音和识别；约每 250ms 检测当前可编辑输入框。无输入框时保存未送出内容，切回并点进输入框后恢复后续定稿，已留在记忆里的旧内容不会重发。后台按音频采集阶段标记片段，离框期间的音频即使晚返回也只进缓存；恢复输入后旧缓存仍保留，必须手动复制、粘贴；复制只用失焦后胶囊右侧的按钮（Ctrl+C 不被接管，始终是原应用的普通复制）。不会强行跳回旧窗口；编辑手势或修饰键按住时暂缓送字。可编辑性判定是三态：可写就送字；只读文本框仍进缓存；Electron、Flutter、自绘外壳优先用 MSAA 获取实际焦点：WorkBuddy 可编辑输入框送字，只读文件预览进缓存；真正无法报告输入目标的窗口仍按“无法确认”保留兼容送字。
3. 外形只由输入焦点决定，录音中和空闲时都一样：有可编辑输入焦点为圆形（上屏模式）；失去焦点即为胶囊（缓存模式），不等待说话、草稿或定稿。空闲时每 400ms 复查焦点，形状随焦点来回变化，不必先录一句话才知道结果。有未上屏缓存时胶囊始终是复制按钮，与焦点无关。
4. 无焦点胶囊无文字时显示“监听中”；人声、待识别队列或正在运行的识别/标点任务未结束时显示“转写中”，复制文字变灰并禁用。任务全部完成且有缓存时亮起“复制/已复制”；圆形和胶囊讲话时显示白色细声纹，静音监听时切回白色麦克风，双层浅色波环持续向外扩散，石墨表面轻微明暗呼吸。输入目标和音频分界确认后切回圆形，避免恢复期间反复闪烁，只输入后续新话，旧缓存不自动补发。空闲时仍可通过胶囊复制保留的内容。
5. 录音中点击胶囊左侧声纹（含圆形中心位置）结束录音，点击右侧“复制/已复制”只复制，不停录音。空闲时点胶囊：有未上屏文字时复制，没有缓存（空闲椭圆、显示“未开启”）时直接开始录音。长按约 0.4 秒先收尾，再开始全新录音；新会话成功开始后清空上一轮缓存；松开不会误复制或停止，新一轮可以再次轻点结束。拖动取消长按。右键菜单是白色卡片，三项各带图标（收起 / 词典 / 退出），点窗口外任意位置、按 Esc 或选任一项即关闭；录音开关用 Win+H 或左侧按钮，复制只用右侧按钮，清空旧缓存用长按开始新一轮。有待处理内容时提示“转写中”，停顿或结束收齐定稿后可复制。
6. 连续说话会分段处理，每次录音最多三分钟。拖动可以移动位置。无输入框或窗口切换不触发结束；圆形麦克风时点击结束，胶囊时点左侧声纹或按 Win+H 结束；三分钟上限仍会结束录音。
7. 记忆仅存在当前程序内存中，退出后清空，不保存到磁盘。无法确认可编辑性的应用保守进入记忆模式；SendInput 成功仅表示系统接受送字，不能保证所有应用实际采纳。

麦克风圆形直径 72，胶囊约 106×42（两端半圆、中间直边），按相同面积变形；完整透明画布为 128×96。共用底图与材质直接跟随矢量外轮廓，监听显示向外扩散的双波环，不增加独立的实心内圆。麦克风与胶囊使用逐像素透明窗口，外轮廓保留半透明抗锯齿，不使用硬边窗口裁剪。状态提示不展示听写正文。讲话/静音状态由 Silero 人声检测决定，音量只控制声纹幅度，避免放大后的底噪使声纹常驻。音频仍从 Windows 默认麦克风采集；没有更改系统输入音量。

形变使用接近零回弹的收敛弹簧：约 256ms 完成 90% 变化、304ms 完成 95%，到达后不反复摇晃。快速切换时保留当前形状与速度，不从头播放；监听波环、圆形大图标到胶囊小图标的连续缩放保持现有行为。

## 当前架构

`默认麦克风 PCM16/16kHz → Silero VAD → SenseVoiceSmall → 热词复解（可选，仅定稿） → 个人词典（可选替换） → 草稿增量输入 → 标点校验与定稿去重 / 未上屏记忆 → 点击复制`

- SenseVoiceSmall 是非流式识别模型。这里实现的是**分段识别**，当前句约每 350ms 尝试识别，草稿返回后直接尝试写进目标输入框，属于增量上屏，不是模型原生逐 token 流式。首次尝试需约 550ms 音频，再加推理和送字耗时。
- 声音检测统一使用 100ms 片段，缓冲积压形成的大包先拆分，防止检测与定稿依赖切回输入框才触发。声音检测使用最多 32 倍自适应增益；ASR 保留原始波形，每段统一调整音量，避免逐帧增益扭曲轻声与辅音。
- Silero 阈值 0.30、最短语音 120ms、静音分段 650ms；首尾留 400ms。持续说话到约 10 秒时，在附近较安静的位置切开，剩余音频进入下一段。
- 当前句约每 350ms 尝试更新，过期草稿被替换，不积压成待处理任务。定稿段按顺序处理，并与已送出的草稿对齐去重。每次取新旧草稿最长公共前缀，只替换变化的尾部，可修正文中间的词句和标点；退格范围限制在本轮写入的当前段。已完成段落不再回改。失焦、手动编辑或送字不完整时停止修订：最终结果仍与已处理草稿一致则只缓存剩余后缀，否则缓存最终整句并标记，供手动恢复。无焦点时草稿仍只在内部处理，定稿进缓存。
- 关闭 ASR 的 ITN 数字改写；固定语料发现它会误写金额。独立标点模型只允许添加标点，改变正文、数字或英文词边界，以及删除或替换已有标点（如 `.NET` 的点）的结果会被拒绝并保留原文。
- CPU 识别 4 线程、VAD 1 线程、标点 2 线程。不编译 Vulkan 着色器，不占用独显模型显存。
