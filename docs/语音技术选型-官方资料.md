# Windows 语音输入选型：官方资料核验

核验日期：2026-10-20。范围：中文为主、夹英文技术词、替代 Win+H 的本地语音输入。此文记录资料与选型推论，不代表新增本机实测。

## 结论

不要仅凭品牌把首遍识别换成 Nemotron。建议保留已经跑通的低延迟流式首遍，增加一个能使用个人词表的句末复核候选；优先对照 Fun-ASR-Nano 与 Qwen3-ASR，再决定是否值得增加第二模型。Nemotron 3.5 ASR 可保留对照和标点实验价值，但“中文最快最准”的结论没有证据。

仓库已有 [P0 实测](桌面端-Nemotron3.5-P0实测-2026-10-20.md) 可作为候选筛选线索，但不能直接作为最终名次。本轮主任务检查发现：旧计分在英文分词前删除空格，英文 WER 与混合单元错误率需修正重算；首字记录取音频样本进度并排除了未出字样本，并非完整墙钟延迟。已有结果支持“先保留首遍做对照”，不支持断言某模型绝对最快最准，也不能把默认配置首字时间解释为模型不可降低的地板。

## Nemotron 的名称、支持与限制

- 用户应选的完整型号是 **nvidia/nemotron-3.5-asr-streaming-0.6b**，不是同品牌的聊天/视觉推理模型，也不是旧的英语专用 **nemotron-speech-streaming-en-0.6b**。新模型是 600M 参数、原生流式 FastConformer-RNNT，带标点与大小写；官方发布日期是 2026-06-04。[官方模型卡](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b)
- 普通话 zh-CN 被列为 **Broad-coverage**，不是最高的 Transcription-ready 档。官方 FLEURS 表中中文 CER 随语言条件/分块设置约为 19%–22%。这是公共测试集指标，不能直接与本地 174 条、其他模型不同测试集横比。[官方模型卡语言表与评测](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b#performance)
- 80/160/320/560/1120 ms 是模型分块配置，**不是麦克风开口到屏幕首字的保证**；采音、前端、右上下文、解码、断句、插入都会增加实际延迟。[官方流式配置](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b#setting-up-streaming-configuration)
- 官方 NeMo Python 集成主要列 Linux/NVIDIA GPU；与此同时，**NVIDIA/NeMo-Speech.cpp** 是官方本地 C++ 路线，提供 Windows 安装、CPU、CUDA/Vulkan 等构建与稳定 C 接口。不能概括成“没有 NVIDIA 显卡就不能跑”。官方 CPU 示例的 27 ms/160 ms 分块测的是英语模型，不能移植为用户本机中文指标。[官方 C++ 运行时](https://github.com/NVIDIA/NeMo-Speech.cpp)
- 官方 SDK 存在 `speech_contexts` / `boost` 参数，但这不证明当前具体 RNNT、解码器、中文热词端到端已经生效；同一头文件注明当前 N-best 实际仍只返回一个结果。选型前要测试真实术语召回与误增强。[官方 SDK 头文件](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/include/nemo_speech/asr.h)

**本地与上游版本必须分开判断：**官方 main 宣称支持模型，不等于本机 0.2.0/nightly 构建支持当前下载 GGUF。仓库 P0 文档记录了架构字段加载失败及改用 transcribe.cpp 的过程，应沿用可复现构建，不能仅因网页更新就宣布故障解决。

## “越说越准”应怎么实现（设计建议）

1. **先学文字偏好，不实时改模型权重。** 用户纠正“识别片段 → 正确词/短语”时，本地保存正确写法、发音/读音、频次与上下文。下次给支持热词的解码器或句末模型；默认不把每句输出当作真值自学。
2. **把纠正和润色区分开。** 删除口水话、改变句式不是声学识别的训练标签；只把可信的局部纠错计入个人词表。用候选选择、撤销、再次纠正控制错误学习。
3. **句末复核做有边界的修正。** 只处理当前尚未提交的句子，保留录音与原识别以便回退；不要让生成式模型随意补内容。软件名、联系人、英文缩写是首批评测重点。
4. **后续有数据再评估微调。** Nemotron/SenseVoice 的官方资料提供微调路径，但没有证据支持“普通运行时听几次会自动更新声学模型”。个人录音、可靠修正对、未见过的测试集准备好后，才能判断微调是否比词表更划算。

这些是工程方案，不是上述模型已经内置的完整个人学习功能。应验证：纠错后下次召回、相关句不误改、关闭重开仍保留、删除词条后可撤销影响。

## 决策门槛

当前只需要一个小规模同音频对照，别先集成全部模型：现有首遍作基准，Fun-ASR-Nano 和 Qwen3-ASR 先各跑同一批中文、中英混说、软件名/人名/数字、长短句和安静/键盘声录音。分别记录首字时间、说完后定稿时间 P50/P95、字词错误率、术语召回率、标点正确率、误改次数、CPU/显存/常驻内存，再选一个胜出的复核模型。

RTX 5060 Ti 8GB、Ryzen 7 9700X 来自既有项目文档，硬件当前状态应由主任务核对。本轮未测候选模型在该机器上的延迟、显存和准确率；没有官方材料能代替这一步。8GB 显存也不是“所有 1.7B 模型与其他常用软件一起运行必然无压力”的保证。
