# Ctrl+C 每轮只接管一次

版本：1.6.28.0；日期：2026-10-22；状态：现行。

原因：1.6.13.0 用 `recoveryCopied` 同时表示按钮已复制和快捷键已使用。`KeepRecovery` 每次追加识别片段都会清掉这个标志，导致成功复制后，后续片段再次抢占普通 Ctrl+C。对本轮旧正式 EXE 的内存测试复现了“复制成功 → 追加片段 → ShortcutCopyReady 再次为 true”，不读写用户剪贴板。

修改：`app/Microphone.cs` 增加本轮 `shortcutCopyConsumed`。缓存复制成功即消耗本轮快捷键机会，按钮复制也遵循这一点；追加片段仅更新按钮的已复制状态，不重置快捷键。只有后台确认成功开始新轮后才重置。首次复制失败可重试，已放行后的按钮失败不会重新接管。图标仍可重复复制最新缓存。

验证：正式 EXE 在真实交互桌面串行执行 `--self-test`、`--hotkey-test`、`--smoke-test`，退出码均为 0，结果文件时间均属于本轮且为 PASS。

- `work/microphone-self-test.txt`：首次失败重试、复制成功、追加十个片段并连续十次普通 Ctrl+C 放行、迟到的快捷键消息不覆盖、按钮失败及重试、收起保留放行状态。
- `work/microphone-hotkey-test.txt`：真实 SendInput Ctrl+C 首次拦截，释放后连续十次穿过键盘钩子。测试不读写剪贴板。
- `work/microphone-ui-test.txt`、`work/microphone-round-reset-test.txt`：真实模型握手，成功开始新轮重置消耗标志，停止和收起保留缓存，启动失败保留缓存。

范围：未修改识别链路、模型或用户数据。未代替用户实际聊天窗口中选中文字并复制粘贴的验收。
