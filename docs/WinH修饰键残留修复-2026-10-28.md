# Win+H 修饰键残留修复

版本：1.6.78.0；日期：2026-10-28；状态：现行，原生回归通过，日常长期使用待验。

用户报告 Windows 语音与 VoxFix 同时出现。现场确认 `--hotkey-host` 和 `--background` 均在运行，登录任务 Running，不能归因于入口缺席。系统级 RegisterHotKey 备用注册返回 1409（已占用），未采用。

## 复现与修复

`ShortcutKeys` 原来只在启动时读取实际修饰键，随后依赖历史按下/松开事件。另一钩子吞掉 Shift/Ctrl/Alt 松键时，本地集合残留按下状态；下一次 Win+H 被当成额外组合键放行。VoxFix 已显示时，这会导致系统语音也出现。这是已复现的漏洞，尚不能确定是用户现场的唯一触发原因。

回归在快捷键线程注入残留状态，再用真实 SendInput 重放 Win+H。修复前 `--hotkey-test` 在左 Shift（160）失败：`Stale modifier must not leak Win+H to Windows: 160`，退出码 -532462766。修复后八个修饰键在 H/Esc 按下前重新读取 GetAsyncKeyState，清除过时状态；已捕获的 H 重复和松键仍由原逻辑消费。主程序和 HotkeyHost 共用 DictationShortcut。

未修改模型、个人词典、识别协议、送字规则、系统语音设置或登录任务。
