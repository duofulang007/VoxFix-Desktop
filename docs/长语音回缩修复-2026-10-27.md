# 长语音回缩修复

版本：1.6.73.0；日期：2026-10-27；状态：历史。用户反馈光标跳动后，差异修订方案已由[1.6.74.0稳定短句](稳定短句与长会话-2026-10-27.md)覆盖。以下旧版自动检查和对照数据保留，不代表其主观输入体验可接受。

## 原因与改动

用户报告长语音时，已输入文字反复大幅缩短再长出来，输入框因换行减少而忽大忽小。

用用户提供的 ElevenLabs Scribe v2 教程 MP3 前175秒，按100ms音频包、原速进入当前生产 R5 INT8 / VAD / 词典 / 标点 / 救援链路。不使用麦克风，不启用听写历史，不训练。音频 SHA256 为 `ab78e6c0fe527ab11e1eb3494849a4f3012b5de3ab1ec800ad11ea0162b89948`，原 `recognize.py` SHA256 为 `dd81010d2a5a37a86681d1b51f08f85a94f9633a31265ac921b5840de43c4cd7`；识别源码本次未改。

捕获389次草稿/定稿变化、20个定稿段。分段持续推进，没有证据表明整场录音被当成一个草稿；连续讲话的当前段可较长，最长实际定稿音频范围13.021秒。初版诊断脚本用12秒作上限的断言失败，这个过严假设不是产品故障判定。复现记录完整落盘。

直接原因是 `Microphone.ReviseText` 原来只取最长公共前缀，然后退格删除全部不同尾部、重打新尾部。模型在英文段开头修改一个标点、空格或少数词时，后面的正确正文也被重复删除；当前段越长，放大越明显。记录中多次公共前缀为0，即从当前段第一个字开始重写，不代表越过定稿段或删除用户原文。

新版在当前段的新旧文字间找共同序列，只移动光标并插入/删除差异，保留仍正确的正文；完整执行后光标自然停在新段末尾。纯追加、短分批、标点草稿合并不变。数字、否定及定稿仍能修正，不冻结错误文字。

输入保护仍先核对前台、焦点和编辑状态。同步字符消息通道逐对核对焦点/许可，支持左右与Delete的扩展键标记；仍拒绝换行，不读取剪贴板，不自动发送消息。部分送出按实际完成的移动/删除/插入重建账本，再停止修订并保留最终结果，不在中间光标位置继续追加。

显式CR/LF的光标计数和超过一百万格的差异矩阵保守沿用旧尾部替换，避免跨行计数错误与过大分配。实际识别文本本身明显缩短时，仍可能有小范围回缩，不能承诺所有软件零跳动。
