# 草稿即时上屏与当前段修订

版本：1.6.25.0；日期：2026-10-22；状态：现行。

## 行为

SenseVoiceSmall INT8、VAD 和标点模型保持现有配置。识别出的当前段草稿立即尝试进入输入框；继续说话时允许修订这段文字，停顿定稿时补齐最终结果和标点。用户明确允许改写已上屏草稿，本记录取代旧文中“所有已上屏文字永不回改”的限制。

只修订本轮在当前输入位置写入、尚未完成的段落，不修订用户原有文字或已完成段落。比较新旧草稿的最长公共前缀，通过带自有输入标记的退格和 Unicode 输入替换变化的尾部；重复结果不重复送字。最终结果可以比草稿更短，也可以修改金额、否定词和正文中间的标点，不按特定词句替换。

手动编辑、焦点变化、修饰键操作或送字不完整时停止修订。失焦期间的草稿不输入、不提前当定稿缓存；最终结果与已处理草稿前缀一致时缓存剩余后缀，否则保留标记过的最终整句供手动恢复。回到输入框只送新阶段的话，旧缓存不自动补发。无障碍判定、只读保护和缓存生命周期保持现有约定。

## 实现

- `app/recognize.py`：快照新增 `preview_segment`；最终片段携带 `preview_start`，即使停止时扩展了实际音频范围，也能与同一 route 的草稿对齐。切换阶段、入队定稿时清空当前草稿；过期识别不能冒充新阶段草稿。异常回复携带先前完成的片段，避免 UI 把整场定稿重复输入。
- `app/Microphone.cs`：`ApplySegment` 按片段跟踪已处理草稿，`ReviseText` 仅修改其变化尾部，并同步送字账本。未提前上屏的最终片段仍沿用原来的送字规则与空格。最终片段按索引去重。
- 不新增依赖，不换模型，不改变 UI 几何、快捷键或录音参数。当前句约每 350ms 尝试识别，首次尝试需约 550ms 音频，再加推理和送字耗时；不是原生逐 token 解码。
