# 中文与中英混说：Nemotron 后续纠错选型

日期：2026-10-20。仅研究，没有下载模型或修改程序。推荐是待测候选，不代表已在用户真人录音上胜出。

## 结论

保留现有 Nemotron 实时识别时，可以在句末接纯文本纠错器，技术上不依赖某个 ASR 品牌。本轮没有找到官方证明“专门搭配 Nemotron 3.5、中文/中英混说最佳”的社区组合。优先比较专用中文纠错模型 ChineseErrorCorrector4-4B 与通用 Qwen3.5-4B 的保守编辑；如果大量英文术语已经听错成中文，带音频的二遍识别更值得测，因为只看文本不能可靠恢复原始发音。

## 对当前项目的判断

主代理本轮核验：RTX 5060 Ti 总显存 8151MiB、当时占用约 1793MiB；这是瞬时状态。4B 模型的 BF16 权重约 8GB（按参数量粗算，不含缓存、运行时和桌面占用），不能据此保证原精度完整驻留这张卡。量化版本可以列入评测，但正确率、运行时兼容性、实际峰值显存和首次加载延迟仍需测；不提供未经实测的每句毫秒数。

主代理本轮还实际检查了当前 transcribe.cpp 模型能力：`vocabulary`、`context_prompt`、`instruct`、`transcript_prefix` 均为 False。即使原始模型或其他运行时提供热词，也不能直接声称当前 GGUF 流式已经能接热词。要使用热词，需换到明确支持的模型/运行时路径并验证。

## 怎样测才有用

1. 保留已有 Nemotron 的结果作对照；分别试 CEC4 与 Qwen3.5-4B，一次只跑一个纠错器，比较纠正多少、改坏多少，以及句末延迟。
2. 必须包含正确文本和中英术语：GLM、Kimi、Blender、型号、版本号、数字、否定词。不能只用原来有错的中文句子证明纠错有效。
3. 只允许局部必要修改；英文原样保留是默认，已知词表可提供上下文，但不能靠全局字符串替换修复多义词。模型名和版本号不能凭“听起来像”擅改。
4. 如果首遍把整个英文名变成中文，额外测 Fun-ASR-Nano 或 Qwen3-ASR 二遍音频识别。音频只需在本次会话内存中短暂复用；不能因为测试二遍就恢复用户已拒绝的未输入文字保存功能。
5. 当前产品是向任意目标输入框只追加文字。纠错后要替换已上屏文字还涉及输入提交方式；模型接上不等于能安全回删并替换用户正文。最小验证应先对比结果，再选择句末提交等明确的输入策略。

这些是工程建议和基于模型输入信息的判断。未做实际纠错推理、用户录音基准、量化验证或完整 Windows 集成；纯文本模型始终存在把正确专业词改坏的风险。
