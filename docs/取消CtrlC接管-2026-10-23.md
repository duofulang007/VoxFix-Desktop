# 取消 Ctrl+C 接管

- 版本：1.6.32.0
- 日期：2026-10-23
- 状态：现行

## 决定

键盘钩子不再捕获 Ctrl+C。复制未上屏缓存只有一个入口：胶囊右侧的“复制/已复制”按钮（可重复点）。

## 原因

1.6.8.0 起 Ctrl+C 被当作复制快捷键接管，后续在 1.6.13.0 收紧为“复制一次后放行”、1.6.28.0 再改为
“每轮只接管一次”。两次修补都说明同一件事：**全局键盘钩子抢占一个系统级通用快捷键，边界永远说不清**——
用户复制页面里的文字时，钩子要先判断“有没有未上屏缓存、这一轮复制过没有、焦点在不在自己窗口”，
任何一条判错都会吃掉用户真正想复制的选区。这条捷径的收益只是少点一次按钮，代价是劫持系统快捷键。

## 改动

`app/Microphone.cs`：

| 位置 | 改动 |
|---|---|
| `ShortcutKeys.Process` | 删除 `ctrl+0x43` 分支，命令只剩 1（Win+H）与 2（Esc）；`available` 不再有“可复制”位 |
| `DictationShortcut` 可用位 | `UpdateShortcutState` 只写 `1`（可见），不再叠加 `2` |
| `HandleShortcut` | 删除 action 3 分支；迟到的 action 3 消息落在 `action != 1` 直接返回，不复制 |
| 状态字段 | 删除 `shortcutCopyConsumed` 与 `ShortcutCopyReady`；`recoveryCopied` 保留，只表示按钮已复制 |

未改动：缓存内容、`CopyRecovery` 的行为、胶囊按钮的可重复复制、新轮开始清缓存、Win+H 与 Esc。
钩子仍会吞掉被打包的 Win+H / Esc（`swallow`），所以这两个动作依旧不落到目标应用。

## 验证

- `--self-test`：钩子层在有缓存（`available=3`）时对 Ctrl+C 返回 0 且不吞键；连续十次 Ctrl+C 全部放行；
  `HandleShortcut(3)` 不写剪贴板、不复制迟到消息；按钮复制成功/剪贴板忙/重复点击/追加片段后重新可复制全部保留。
- `--hotkey-test`：真实 SendInput 一次 Ctrl+C + 十次连续 Ctrl+C 全部穿过钩子（只由编辑保护计一次按键，`calls` 不变），
  Win+H、Esc、鼠标保护行为不变。不读写用户剪贴板。
- 结果文件：`work/microphone-self-test.txt`、`work/microphone-hotkey-test.txt`。

以及 `HandleShortcut` 的 action 3 分支复原（见 Git 中 1.6.31.0 提交）。相关文档
