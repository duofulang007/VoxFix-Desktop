## 2. 第一版做什么

### 2.1 新建规则默认不限语言（P0）

- 做法：`WordGroup.Context` 默认改为空串（空 = 任何语言都替换）；`Save()` 只在非空时写 `context`。等价于"新建规则写进 JSON 时不带 `context` 字段"。
- 旧规则：**一条都不静默放开**，读文件仍按原值原样写回（`context:"zh"` 继续是 `"zh"`）。审查结论见第 3 节。
- 一处容易被忽略的连带行为：现在只出现在 `hotwords` 里、还没有错法的词，内存里 `Context` 也是默认 `"zh"`；默认值改空之后，这类词**以后第一次补错法会写成"不限语言"**。这正是"新建规则"该有的语义，但要在验收里显式覆盖。
- 连带必须改的文案与断言：
  - 帮助说明 `Microphone.cs:926` 的"新建纠错规则仅在整段话含中文时生效，纯英文不替换"要删。
  - `--dictionary-test` 里 `:1416` 断言帮助文本含"纯英文"，必须同步改成新口径。
- 不做：不加语言开关，不加"仅中文/仅英文"选项，不改 `context` 的解析语义（非 `"zh"` 仍视为全局）。

### 2.2 简单搜索（P0）

现状没有搜索，全部靠 41px 行高的列表翻。

- 位置：词语列表顶部，`listClip`（34,160,248×410）内加一个搜索框，列表高度相应让出约 36px。**这会动几何，必须重跑 `--dictionary-test` 并看新截图。**
- 匹配：`Word` 或任一条 `Variant` 含查询串即命中，`OrdinalIgnoreCase`，不做拼音、模糊、正则、排序。
- 索引映射：新增 `visible: List<int>`（可见行 → `groups` 下标）。`PaintRow`、`OnSelected`、`ShowWord`、`RefreshList`、删除与撤回全部改走映射——这是本次**唯一有回归风险的改动**，必须逐项覆盖。
- 交互约定（避免丢编辑）：
  - 过滤前后先 `Commit()`；右侧编辑区**不随过滤清空**，只有用户点另一行才切换。
  - 状态栏显示"命中 n / 共 m"。
  - `Add()` 命中已有词时，如果该词被当前查询过滤掉了，先清空查询再定位。
- 复用：重复词定位（`Index()`）和错法冲突检查（`Save()`）已存在，**不重写**；搜索只是让"找到它"变快。
- 冲突提示仍按现有口径：**保存时**跨词冲突拦截并给出两个词名，不静默覆盖。第一版不新增"打字时实时拦"的阻塞规则。

### 2.3 替换预览（P0）

- 入口：词典窗口内一块预览区（输入一句 → 显示纠正后文本 + 命中条目列表）。
- 必须复用生产替换代码，不能另写一份：把纯文本层抽成 `app/dictionary_rules.py`（`dictionary_pattern / load_dictionary / load_dictionary_text / has_chinese / apply_dictionary` + `HOTWORD_LIMIT`），`app/recognize.py` 改为从它导入并保持对外名字不变（`tools/test_sensevoice.py`、`work/dict-replay-20261023.py` 的 `from recognize import ...` 不受影响）。
- 通道（推荐）：新增 `app/dictionary_preview.py`，从 stdin 读 `{rules, hotwords, text}`、把结果写回 stdout，**只读、不落盘、不加载模型**。抽层之后它只 import `re`，单次约 100–200ms；不碰常驻识别子进程，不会和录音抢请求。
  - 已排除的替代：给 `recognize.py` 加 `preview` 操作（要和录音期间每帧 poll 串行化，风险高）；在 C# 里重写替换（一定漂移）。
- 预览的输入是**编辑器当前内容**（含未保存改动），不是磁盘文件——否则预览和"保存后实际行为"对不上。
- `force` 口径：按"单句"判断，即 `has_chinese(输入)`；这与实际单句听写一致。必须在预览区标一句"输入含中文时，仅中文生效的旧规则也参与"。
- 命中信息：命中的词条、命中的那条写法、位置；被 `context:"zh"` 跳过的规则单独列"未生效（旧规则仅中文）"。为此 `apply_dictionary` 增加可选 `hits` 参数（默认 `None`，生产路径不变）。
- **明确边界**：这是文字纠正预览。它不跑识别、不放音频，所以看不到热词救援，也不能用来判断"这个词能不能听对"。窗口文案必须写清楚。
- 超时/失败：2 秒放弃并显示"预览暂不可用"，不阻塞窗口、不影响保存。

### 2.4 把 64 词截断变成可见（P0，最小方案）

先分清三个数字，任何地方都不许混用：

| 数字 | 含义 | 现在 |
|---|---|---|
| 保存的词数 | `hotwords` 数组长度 = 编辑器里的词条数 | 13，无上限 |
| 参与救援的词数 | `min(64, 有效词)`，按文件顺序取前 64 | 13 |
| 错法替换规则数 | 有错法的词条数（及写法总条数） | 13 条 / 49 个写法，不受 64 影响 |

最小方案（不改识别行为、不丢数据）：
1. `recognize.py` 的 `[:64]` 换成具名常量 `HOTWORD_LIMIT = 64`（放在 `dictionary_rules.py`），**截断规则本身不变**。
2. 详情区/状态栏显示"词语 13 · 参与救援 13/64 · 纠错规则 13"；总数超过时补一句"末尾 N 个词不参与近音救援，仍可用于错法纠正"。
3. 保存时若超过上限，在状态栏给一条**非阻塞**提示（不阻止保存）。
4. 帮助说明和 README/使用说明改写为上面三个数字的口径，删掉容易读成"词典上限 64"的说法。
5. `--dictionary-test` 用 80 词夹具断言：状态为 80 / 64，且第 65 个词不在参与救援的集合里；C# 侧常量与 Python 常量一致性用一条纯文本断言守住（读 `app/Microphone.cs` 比对字面量），避免两份值漂移。

扩容（真正的 64→更多）**不在第一版**：要先有第 6 节的延迟、内存、误救数据。删除限制或承诺"无限词数"都不做。

### 2.5 两种能力写清楚（P0，文案级）

- 只填正确词：**只加入救援词表，不保证听对**（模型不一定能听出来，听不出来就保留原文）。
- 填了错法：识别结果出现该写法时**一定**改成正确写法。
- 落点：帮助说明、详情区"容易识别成"标签旁的动态提示（"未填写：仅参与近音救援" / "已填写 N 条：命中时纠正"）、README 与使用说明。第一版不加徽标、不加分类字段。
- 纯中文术语当前拿不到同等救援（第 1.2 节实测）。第一版**不修** `hotwords.py` 的字符范围，只在文案里如实说明；英文术语是重点，不转成中文专项。

|---|---|---|---|

| JSON | zh | `Jason`/`jason` 是真人名 | 保持 zh。要在纯英文里也纠正，就得把 `Jason` 从该词条移走（一条词条只能有一个 context），收益待数据 |
| Codex | zh | `cols`、`kos` 分别是英文缩写/真词 | 保持 zh |

| git status | zh | `get status of the job` 是正常英文 | 保持 zh |

| 什么（`什麽`） | zh | 错法是中文，语言限制没有实际作用 | 可放开（影响为零），可随机制一起验证 |

## 4. 替换语义核对（只纳实际相关）

| 点 | 现状【已确认】 | 第一版处置 |

## 6. 验收方案

模型固定为当前 R5 INT8，音频相同，**只变 `dictionary.json`**，两组以上 A/B：

- A：现状词表（zh 保留，13 词）
- B：加术语后的词表（新建规则不带 context）
- C（只在需要时）：80 词词表，验证 64 词参与数与尾部行为

语料分层（每条都要"裸念 + 句中"两版）：

| 组 | 内容 | 目的 |
|---|---|---|
| 1 | 英文术语裸念（GitHub、Python、Kubernetes、TypeScript、VoxFix、JSON、API…） | 单独念能不能对 |
| 2 | 纯英文句子含术语 | 放开语言限制后的正向收益 |
| 3 | 中英混说（"这个 API 返回 JSON"） | 原有强项不能退步 |
| 4 | 中文术语（裸念 + 句中，如"梯度下降"） | 如实记录：只靠错法替换 |
| 5 | **普通英文词组控制组**（`get up at seven`、`Jason called`、`soul music`、`get status of the job`） | 误改硬门槛 |
| 6 | 不含术语的普通句 | 误插/误改 |
| 7 | 静音、轻声 | 空输出、不误插 |
| 8 | 80 词词表同音频 | 64 词边界 |

指标与门槛【建议】：

- 术语精确命中（正确写法完全一致）、整句 exact、单位错误数（`tools/p0_score.py` 的 `units`）。
- **控制组误改必须为 0 条**，任何一条误改都否决放开对应规则。
- 术语组提升需可见（例如至少 +5 条或多 10pp），否则不为此扩表。
- 定稿延迟 p50/p95 不高于现状 +20ms（词典层是正则，理论上近零）；worker RSS 无增长（词典层不新增模型）；救援触发次数与 64/80 词条件下的差异单列。
- 不可退步项：草稿立即上屏、用户编辑保护（手动编辑/失焦停止修订）、未上屏缓存与复制、标点不重复。

工具顺序：

1. 零模型先筛：`work/dict-replay-20261023.py`（封存 1,314 / 新留出 840 / AISHELL 2,307）看"改对/改坏"条数。
2. 固定音频 A/B：`tools/evaluate_sensevoice.py --manifest <新语料清单> --output <新文件>`（不覆盖旧结果，记录音频与模型哈希）。
3. 只有改了救援口径才跑 `work/hotword-prototype/p2_prod_eval.py`。
4. 原生：`--dictionary-test`（含本轮 `TIDY-TEST PASS`）、`--self-test`、`--stream-test`；旧 174 条仅作辅助回归，不代替独立语料。
5. 最后用真实麦克风按语料念一遍，重点 20 条，确认实际听写与缓存行为。
