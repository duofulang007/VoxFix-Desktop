# 英文读成天城文：原因与修复

日期：2026-10-20。本轮只改识别脚本 `app/recognize.py`，未改界面、未改输入方式、未改模型文件。

## 结论

用户读 “Blender、GitHub”，程序输出 “पल कि हाप प्लैंडर हिहाबल”。原因是**模型的自动语言选择跑到了印地语（hi-IN）**，不是编码、不是麦克风、也不是 Qwen。

日用链路一直没给 `language` 参数，Nemotron 3.5 因此在 32 种语言里自己猜；英文短句在口音、远近场或语速变化时会猜成 hi-IN / vi-VN 等，然后用那套文字转写英文发音。强制 hi-IN 解英文，得到的正是同型天城文：

| 音频 | 强制 hi-IN 的输出 |
| --- | --- |
| sentence-0（Please send me the file before tomorrow morning.） | प्लेस सैंड मी द फाइल बॉफ़ेर टोमो मॉर्निंग |
| sentence-7（I use Kotlin and Python to build Android applications.） | इज कटल एंड प्लस टू बिल्ड एंड्रोइड एप्लीकेशन्स। |
| word-13（GitHub） | गुब |

用户的输出里 `प्लैंडर`（plandar）对应的正是 Blender，格式完全一致。

修复方式：**首段文字出来之前先检查文字种类**。落在中文/英文之外就判定语言猜错，用缓存的音频按 zh-CN 与 en-US 两个假设重解，取“有结果且平均 token 概率更高”的那个，再继续这段录音。此时还没有任何文字被送进目标窗口，所以不存在删字、回删、覆盖剪贴板。

### 自动语言确实会漂

| 样本 | 劣化 | 自动语言输出 | 首段文字 |

## 修改内容

只改 `app/recognize.py`：

1. 首段文字（约 1.0–1.2 秒出现）若含中文/英文以外的字符（天城文、泰文、西里尔、假名、谚文、越南语扩展拉丁等），判定语言猜错。
2. 用缓存音频（最多 15 秒）分别以 `zh-CN`、`en-US` 重解，按“有无文字 → 平均 token 概率”取优，然后以该语言继续这段录音。
3. 若重解后仍是外语（或已有文字被送出后又出现外语），停止输入并报“识别结果出现非中文/英文文字”，不再继续灌入幻觉文字。已输入正文不回删。
4. 正常路径零改动：不重建、不加延迟、不换模型、不加词表、不做字符串替换。

## 交付状态与剩余问题

- 异语言文字：**已修**，天城文不再上屏；代价是极端劣化音频可能“什么都不出”而不是“出外语”。
- 准确率（同音字、英文术语、型号）：**未改善**。这是模型本身与缺热词通路的问题，本轮没有可用证据支持换模型或加二遍。
- 首字：未变（约 1.0–1.2 秒，取决于音频）。
- 程序本体未重新编译：本会话 `csc.exe` 被安全策略禁止，`bin/VoxFix Desktop.exe` 仍是 1.3.1.0、SHA256 不变；识别脚本是运行时由 exe 调用的外部文件，已更新。
- 未做真人麦克风验收。`--capture-test` 只证明采集通路，不证明口音与距离下的识别质量。
- 已知残留：若外语幻觉先吐出一段纯 ASCII 碎片（例如 `Adict`），这段碎片会先上屏，随后才触发停止；已上屏文字不回删，这是现有“只追加”输入方式的约束。
