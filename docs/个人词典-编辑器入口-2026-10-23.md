# 个人词典：编辑器入口与近音骨架

- 版本：1.6.34.0
- 日期：2026-10-23
- 状态：现行
- 前置：[个人词典-解码后词表-2026-10-22.md](个人词典-解码后词表-2026-10-22.md)、
  [热词偏置-救援通道-2026-10-22.md](热词偏置-救援通道-2026-10-22.md)

## 为什么做

用户反馈两件事：

1. **"我读 JSON，结果出 Jason"** —— 这类近音错法（JSON/Jason、WiFi/wiifi）拼写距离是 2，
   原来的近音检测只容 1 个编辑距离，所以连救援都不会触发。
2. **词典功能有用但改不动** —— 1.6.30.0 的词典确实修好了中英混说里的 GitHub，
   但入口只有一个手写的 `dictionary.json`，用户不想每次开文本编辑器改 JSON。

## 做了什么

### 1. 右键菜单「词典…」

菜单从两项变三项：**收起 / 词典… / 退出**。点「词典…」打开编辑器窗口（520×430，深色卡片、圆角，
与菜单同色板），窗口移出桌面边界时也不闪：

- 左侧是词列表（`hotwords` 与 `rules[].to` 的并集，去重保序）；
- 右侧是这个词的错法，**每行一个**；
- 底部：新词输入框 + 添加 / 删除，下面 保存 / 关闭；
- 切换词时自动提交上一个词的编辑；保存用 `File.Replace` 原子替换，识别端按 mtime 自动重载，
  **下一句就生效**，不用重启；
- 有未保存修改时关闭会问一次；`dictionary.json` 读坏时给出提示，保存即重建。

写回的文件结构固定为：

```json
{
  "hotwords": ["GitHub", "Python"],
  "rules": [
    { "to": "GitHub", "from": ["get up", "git up"], "context": "zh" }
  ]
}
```

- `hotwords` 写全部词（参与解码期偏置）；
- `rules` 只写**有错法**的词，`context` 统一 `zh`（只在中英混说句替换，纯英文句子不动）；
- 编辑器会重写整个文件，手上加的未知字段不会保留。

### 2. 近音骨架匹配（救 JSON/Jason 这类）

新增辅音骨架比较：去掉 `aeiouy` 后相等即视为近音。`json` 与 `jason` 都塌缩成 `jsn`，
`wifi` 与 `wiifi` 都是 `wf`。只对 **4 个字符以上**的词启用（`API` 会塌缩成 `p`，太松）。

### 3. 出厂规则补一条 JSON

```json
{ "to": "JSON", "from": ["Jason", "jason", "J son", "j sen", "j-son"], "context": "zh" }
```

这条不依赖偏置：即使救援没成功，解码后的替换层也会把 `Jason` 改成 `JSON`。
代价是中文语境里真说了人名 Jason 也会被改；把它删掉即可恢复。

## 验证

`--dictionary-test` 是离屏自检：把窗口放到 (-20000, -20000) 显示后 `DrawToBitmap` 截图，
再把当前内容写进 `work/dictionary-roundtrip.json`，全程不进入可见区域、不抢焦点。

```powershell
.\bin\VoxFix Desktop.exe --dictionary-test
# DICTIONARY-TEST current=0 text=48 | GitHub:6 | Python:0 | API:0 | JSON:5 | PDF:0 | WiFi:0
```

- 截图 `work/dictionary-dialog.png`：标题、列表六词、GitHub 的六条错法、按钮齐全；
- 往返文件被 Python 侧解析为 **2 条规则 + 6 个热词**，`apply_dictionary("把 Jason 的配置发我")`
  → `把 JSON 的配置发我`。

## 边界

- 编辑器只改 `dictionary.json`，不改热词偏置的 `BOOST`；强度仍是全局 3.0。
- 词典是**枚举**：救不回来的词（Kotlin→coattland、WiFi→wiifi 只是部分情况）还是得靠人写错法。
  真正常用的词清单需要用户录音评测后再定（见救援通道文档）。
- 骨架匹配是宽松规则：4 字符以上的词只要辅音一致就会触发复解，多花 35–60ms；
  复解拿不到更多词表词时会原样保留。
