# 训练交接与验证协议

版本：1.6.67.0；日期：2026-10-25；状态：现行。

应用负责收集、人工标注、挑选、归档和个人新音验证；agent 负责独立训练、导出、全面回归、正式启用与回滚准备。接口不会训练或替换模型。

## 归档给 agent

在「训练 → 待归档」填写批次名、二次勾选，点「归档批次」。批次在 `user-data/training-batches/时间-唯一编号/`，含：

- `manifest.json`：schemaVersion=2，status=`prepared_not_trained`，分组=`unassigned_keep_rounds_together`。保留旧版 `samples[].metadata` 结构，音频与SHA256逐条对应。
- `samples.jsonl`：每行一个样本，方便 agent 无需反复解包嵌套元数据。
- `audio/`：复制原音；`下一步.txt`：实际路径与交接步骤。

扁平字段：`sourceKind/sourceId` 是原记录身份，`audio` 是批次内相对路径，`sha256` 验音频，`promptText` 是补录时提供的朗读内容（日常听写可空），`spokenText/correctText` 是人工听音确认的完整文字，`recognizedText` 是最终识别，`rawRecognition` 是救援前裸识别，`firstDraft` 是首次有效草稿。原记录缺少某识别层时留空，不推测补齐。

`roundId/sourceGroup/createdUtc/durationSeconds/model/reviewed/split` 保留来源依据。普通听写按轮次分组；缺轮次的补录先按UTC录制日期保守分组。split仍为unassigned；agent 必须核查同轮切片、重复、变速派生与会话隔离，划分训练/开发，保护独立封存集。不能把整份批次同时当训练与最终验收。

已有批次只读；后续修改原记录不改旧快照。重复录音可手工纳入新批次，agent须按音频哈希去重。归档失败 `.partial` 目录不视为完成，不自动删除原音。

## 训练后登记候选

agent 保留生产R5基线，在独立训练环境完成微调和同口径ONNX导出、保存实际训练报告，再登记：

```powershell
& '.\.venv\Scripts\python.exe' app/training_review.py register --name '个人微调 第1轮' --archive '实际批次目录' --model '候选model.int8.onnx绝对路径' --tokens '候选tokens.txt绝对路径' --report '训练报告绝对路径'
```

从项目目录执行；`--root` 可显式指定项目根。多来源重复传 `--archive`。登记会校验音频、标签、清单和模型/词表哈希；候选与现模型相同则拒绝。报告是agent的来源证据，不等于应用证明训练质量。候选目录不可覆盖生产资产，也不能在登记后重写同一路径；变化后须重新登记版本。

记录位于 `user-data/training-review/runs/<id>/run.json`，含来源批次和源录音身份。进入听写记录或验证页会读取候选，来源录音及批次显示相应验证状态。

## 个人新音验证

在「验证」选择版本，点「录音复测」输入完整句子、录制、试听并保存。录音时间须晚于候选登记，哈希不能与来源训练或本轮已有验证重复；音频独立保存，不进入普通训练挑选列表。

应用用两个独立CPU会话跑原模型与候选，`language=auto`、ITN关闭，不经过词典/救援，保存原模型、候选、正确全文及模型哈希；不会通过改字伪装成模型改善。推理失败保留待处理原音，可以点击「重试识别」或由agent执行：

```powershell
& '.\.venv\Scripts\python.exe' app/training_review.py list
& '.\.venv\Scripts\python.exe' app/training_review.py evaluate --id '实际版本id'
```

逐条核对后「验证通过」记录个人确认；所有条目须已识别且候选非空，模型、音频、来源清单和报告变化会阻止通过。「打回」必须填写原因，保留失败记录，后续新候选重新登记。通过后追加新复测会清除旧通过结论。应用不将个人结论等同全量评测通过。

## 正式启用由 agent 执行

用户已选择“标记通过，由agent校验并正式启用”。agent 先看通过记录，检查通用中文/英文/混说、否定/静音、同口径导出、延迟/内存、程序协议和实际使用要求；保留旧模型、配置、哈希与回滚方案。个人复测原音仍是验收用途，未经另行规划不能回流训练并冒充独立验收。

完成实际正式启用和启用/回滚报告后记账：

```powershell
& '.\.venv\Scripts\python.exe' app/training_review.py deployed --id '实际版本id' --report '启用与回滚验证报告绝对路径'
```

此命令只核对生产模型/词表哈希已经等于候选，然后标为已启用；不复制模型、不执行启用。模型变化后列表显示已回退。模型缺失/读取失败则报错，不伪装已启用。所有个人数据、训练来源、复测与报告不提交Git。

选择重试：stdin JSON evaluate请求可附 `caseIds` 数组，必须非空、且每个id属于当前版本；只处理所选pending，不能以子集冒充全部验证通过。普通CLI evaluate不传caseIds时仍处理本版本全部pending。UI多选期间只开放相应重试，不提供批量通过/打回。

## 可返回的状态

归档快照不变，侧车 `lifecycle.json` 单独记录可返回业务状态。schemaVersion=1；status为archived或withdrawn；updatedUtc与history记录每次from/to/createdUtc。缺省文件兼容旧批次，视为有效archived。agent使用材料前必须检查状态，withdrawn暂停；登记、追加复测、识别、通过及deployed记账均检查来源，不得仅看manifest的prepared_not_trained忽略侧车。

验证passed/rejected可通过UI「撤回结论」或命令 `app/training_review.py reopen --id 实际编号` 回到awaiting_retest。原decision存入decisionHistory，cases/原音/识别对照不改；新增复测导致旧通过失效也留历史。deployed是真实模型事实，不允许仅reopen改标签冒充模型回滚。
