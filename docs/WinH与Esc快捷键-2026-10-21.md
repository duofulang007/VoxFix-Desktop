# Win+H、Esc 与每轮缓存

版本：1.6.8.0；日期：2026-10-21；状态：现行。

1.6.11 当前契约：Win+H 呼出并录音，再按暂停但保留窗口，再按继续；只有 Esc 从键盘收起。按下就开始，不等 Win 松开。[现行说明](WinH录音暂停与按下响应-2026-10-21.md)优先。

1.6.10 最新规则：Win+H 关闭会立即隐藏，尾字后台收齐；开启直接显示当前焦点的形状，无入场动画。[现行说明](WinH直接开关与首帧形状-2026-10-21.md)优先于下文早期的“停止后保留面板”。

1.6.9 补充：收尾期间再次按 Win+H 会排队重开，不再忽略，见[修复记录](WinH收尾重开修复-2026-10-21.md)。

1.6.13 补充：Ctrl+C 每批缓存只接管一次，复制成功立即恢复普通复制；新增未上屏文字后重新开放，复制失败仍可重试。图标可重复复制，见[修复记录](CtrlC复制一次后放行-2026-10-21.md)。

## 最终操作

- Win+H：隐藏/空闲时原位呼出并录音；录音中再按停止并收齐尾字，面板保留。开始/收尾忙碌时不重复开关，长按只触发一次。
- Esc：仅悬浮窗显示时结束并收起，不退出进程；收起后 Esc 恢复给原应用。
- Ctrl+C：悬浮窗显示且未上屏缓存已定稿时复制缓存，不清空；其他情况交给原应用。没有绑定 Win+Ctrl+H 或 Win+Alt+H。
- 每次后台确认新会话开始后清空上一轮缓存和“已复制”状态。停止、收起保留本轮缓存；启动失败保留旧缓存。普通开始、快捷键开始和长按换轮共用此规则。
- 位置记忆和不抢输入焦点沿用 1.6.7 的行为。

## 系统接管

独立键盘钩子线程只处理指定组合并向 UI 线程发消息；Win+H 的 H 按下和松开均拦截，抑制长按重复，屏蔽单独 Win 松开触发开始菜单。
Esc 与 Ctrl+C 根据当前可见性/缓存可复制状态开放，其余组合正常传递。
送字保护先让下游快捷键消费事件，修饰键本身不算编辑；修饰键按住时原有送字准入仍然暂缓，普通编辑操作仍走原来的兜底。
实现依据：[微软 LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)。

`tools/install-shortcuts.ps1` 只添加当前用户的 VoxFix 登录启动项，运行 `--background`：加载模型并隐藏待命，不自动录音。
不卸载 TextInputHost 或其他系统输入组件，不修改已有的 DisabledHotkeys 设置。
右键“退出”后释放接管，系统 Win+H 恢复；右键“收起”和 Esc 都保持后台接管。
管理员窗口、安全桌面及其他快捷键软件冲突需要单独验证。

安装：`powershell -File tools/install-shortcuts.ps1`。
撤销登录启动：`powershell -File tools/install-shortcuts.ps1 -Remove`，再退出 VoxFix。
