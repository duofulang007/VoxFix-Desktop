# 中文与中英混说：换成 Qwen3-ASR + 显卡伪流式

日期：2026-10-21。改动只发生在 `app/recognize.py`；外壳、圆盘动效、音效、焦点保护、未输入文字丢弃均未改动。

## 结论

| | 旧（Nemotron 3.5 Q8_0，CPU） | 新（Qwen3-ASR 0.6B Q8_0，Vulkan） |
| --- | --- | --- |
| 174 条 exact | 133/170 | **155/170** |
| 中英混说 | 11/16 | **16/16** |
| 粤语（不支持语种） | 0/20 | 7/20 |
| 英文整句 | 7/8 | 8/8 |
| 简单句 / 否定词 / 金额 | 9/12 · 7/8 · 7/8 | 12/12 · 8/8 · 8/8 |
| 长句（13–18 秒） | 6/6 | 6/6 |
| 出字方式 | 逐字流式，首字约 1.1 秒 | 伪流式：长句 1.6–3 秒开始出字，短句说完 0.1–0.7 秒整句出现 |
| 是否改写已上屏 | 会触发前缀保护 | 永不改写，只追加 |
| 显存/后端 | CPU 4 线程 | RTX 5060 Ti Vulkan |

**准确率提升 22 条，混说满分，且没有任何一条因为换模型而永久变差**（唯一退化：`Kotlin` 单独读时被写成 `Cotland`）。

## 为什么换

- Nemotron 的错误集中在英文术语被当音素转写：`Python→PISA`、`Kotlin→coatland`、`Blender→BLAND`、`Kimi→KM`、`国模→国母`。这不是参数问题，模型对中文里的英文词就是弱。
- 同模型热词、beam、右上下文三条路都已实测无效：
  - 右上下文 52 条对照：默认 41、6 → 39、13 → 41；
  - 热词会让 final 改动标点/大小写，触发前缀保护。
- **显卡对 Nemotron 是负收益**：同一份权重 Vulkan 129/170、CPU 133/170，虽然快 1.8 倍（38.2s vs 68.6s / 174 条）。所以"用上显卡"不能靠给 Nemotron 换后端，只能换模型。
- Qwen3-ASR 0.6B 在同一批 174 条上是 155/170，且 30 种语言含粤语。它没有增量解码接口（`supports_streaming=False`），所以流式要靠外层的重复解码实现。

## 伪流式怎么做的

模型只能整段解码，所以"边说话边出字"由识别脚本自己实现：

1. 音频按 100 ms 到达，全部留在内存，同时给 worker 线程；
2. 每 300 ms 用**目前收到的全部音频**再解码一次（13 秒音频约 70–200 ms，跟得上）；
3. 只有连续 **3 次**解码都相同的前缀才算稳定；
4. 稳定的文本还要等 **1 秒音频**之后才提交——提交时取"1 秒前的解码"与"最新解码"的**公共前缀**；
5. 再扣掉末尾 4 个字符（英文不切在词中间）作为缓冲区；
6. 提交过的文字**永不修改**：后续解码如果和它对不上，这一次结果直接丢弃，不删、不覆盖、不回删；
7. 用户停止时用完整音频再解一次，把还缺的尾部补上；如果最终结果与已上屏内容冲突，保留已上屏内容。

第 4 步是关键。实测里 Qwen 在只有 1–1.5 秒上下文时会把 `git status` 听成 `get status`，一旦直接上屏就改不回来。加入"等 1 秒 + 交叉验证"后，`get` 在校验阶段被丢弃，最终输出 `先运行 git status，再执行 git commit。`。

## 实测

### 准确率（174 条，生产协议）

159/174（含 4 条静音应为空），即 155/170 有文本条目，与整段离线完全一致 —— 伪流式没有损失准确率。

分类：轻声/噪声 21/21、普通话简单句 20/20、中英混说 16/16、冷启动 16/16、英文单词 14/16、简单句 12/12、短词 12/12、否定词 8/8、金额/数字 8/8、英文整句 8/8、600ms 停顿 7/7、长句 6/6、静音 4/4、粤语 7/20。

### 出字时机（实时节奏投递）

| 样本 | 时长 | 首次出字 |
| --- | ---: | ---: |
| 英文整句 | 4.1s | 1.6s |
| 中英混说（含 Python） | 5.6s | 1.7s |
| 13 秒长句 | 13.1s | 2.1s |
| 混说（git status / git commit） | 3.9s | 3.0s |
| 短句（≤3 秒） | 1.5–3.0s | 不增量，停止后 0.1–0.7s 出整句 |

长句在出字后持续增长（13 秒句子共 17 次更新），不是一次性出现。

### 停止后的补齐

`tools/test_microphone.py` 实测：2.6 秒录音，停止到出 Final 文本 740 ms（含一次整段解码）。

### 长录音

超过 25 秒后不再增量解码（重复解码跟不上），剩余部分在停止时按 15 秒切段解码。131 秒视频：停止后约 3 秒出全部文本；过程中有 1311 次增量更新，文字持续增长（首句在片头音乐之后才出现，因此该视频的"首次出字"不能代表说话场景）。

### 启动

模型加载 0.75 秒 + Vulkan 首次编译着色器 7.2 秒 ≈ **9.3 秒**到就绪（旧版约 1.5 秒）。这笔开销从"第一次说话"挪到了"打开程序"，否则第一句要等 7 秒。

### 噪声

1 秒/5 秒白噪声、50Hz 嗡声、数字静音：全部返回空，没有幻觉文字。

### 原视频（131 秒，真实音轨）

775 字，1311 次增量更新（每秒约 10 次，文字持续增长）。术语对照：

| 词 | 旧版 Nemotron | 新版 Qwen 伪流式 | 视频字幕 |
| --- | --- | --- | --- |
| 宫殿 | 供电 / 宫点 | **宫殿** | 宫殿 |
| 国模 | 国母 | **国模** | 国模 |
| Blender | BLAND | **Blender** | Blender |
| Kimi | KM | 后段被截断，前文 `K M` | Kimi |
| 小试牛刀 | 小时牛刀 | **小试牛刀** | 小试牛刀 |
| 紫禁城 | 紫金层 | 紫金城 | 紫禁城 |
| 鹈鹕骑自行车 | 题负级自行车 | 徒步骑自行车 | 鹈鹕骑自行车 |
| GLM | GIM | G O M | GLM |

宫殿、国模、Blender、小试牛刀四项恢复；紫禁城、鹈鹕、GLM 仍是同音错误。字幕本身也可能有误，这里只做词语对照，不作为整段 CER。

## 已知限制

- **首字比旧版慢**：长句 1.6–3 秒（旧版 1.1 秒）；短句没有增量，停止后 0.1–0.7 秒整句出现。
- **短句看不到逐字增长**：2–3 秒以内的录音基本是一次性出现。
- **超过 25 秒**停止增量，剩余文字在停止后补齐。
- 启动从 1.5 秒变成 9.3 秒（Vulkan 着色器编译）。
- 早期冻结后的错误无法修正：虽然加了 1 秒延迟与交叉验证，仍不能保证 100%。已上屏的内容不会回删，这是"只追加"输入方式的底线。
- `Kotlin` 单词单独朗读时写成 `Cotland`（整句里正确）。
- 粤语仍只有 7/20，不是可用水平。
- 未做真人麦克风验收；以上全部是固定音频与协议测试。
