# 个人语音纠错与批量训练方案

- 版本：基于 VoxFix Desktop 1.6.47.0 / R5 INT8
- 日期：2026-10-24
- 状态：现行路线方案；采集、审核及批次准备已在 1.6.48.0 实施，详见[实现记录](听写记录与人工训练材料-2026-10-24.md)。模型微调、启用、自动归档与救援退役尚未实施，以下保留完整路线和建议。
- 方案修订：同日按用户后续讨论，日常采集改为「开启后保存听写历史、稍后人工筛选」，取代仅短时内存保留的初稿。
- 目标：平时方便保存「本人语音＋准确文字」，积累后批量改善本人识别；验证稳定的词逐步退出救援池，已处理的问题默认归档。

## 1. 结论

可以做。推荐采用「日常纠错采样＋引导补录＋离线个人微调＋独立验收＋逐词退出救援」的闭环，沿用 SenseVoiceSmall 和当前 CPU 识别架构。

训练改变模型参数，能让首遍识别更适应本人的发音及常用词，不必每次都靠错字替换或二次救援。但它是概率改善，不能承诺一轮后永远不再错；同音词、全新语境、疲劳或换麦克风仍可能出错。识别正确需要声音与上下文共同判断，不是建立一个「声纹对应固定词」的查找表。

「训练完成」「独立录音识别通过」「可以停用救援」是三个不同结论。界面可以让已解决问题从待办列表消失，但应归档而非删除原音、文字和训练来源。

## 2. 当前已有能力和缺口

初稿核对时工作树干净、EXE 版本 1.6.47.0，后台程序正在运行；这是当时的核对结果，本方案修订只编辑文档，未停止或重启程序。

| 当前证据 | 对方案的影响 |
|---|---|
| `app/Microphone.cs` 的 `VoiceSampleStore` 已保存 16kHz 单声道 PCM16 WAV、完整 `correctText`、创建时间和唯一 ID；每词可有多段 | 复用现有采样和试听，不再造一套录音器 |
| 样本保存在私有 `user-data/voice-samples/`，`state` 固定 `collected` | 维持原始采集事实；训练使用情况另外记账，不篡改为「已学会」 |
| `SerializeDictionary()` 目前把窗口内全部词写入 `hotwords`，加载端仅取前 64 词 | 目前「存一个待训练词」可能挤占救援候选名额；必须先解开此耦合 |
| `app/recognize.py` 当前先裸识别，再定稿救援，再词典替换和标点 | 要证明模型学会，必须记录和评测救援、替换之前的结果 |
| `app/hotwords.py` 有会话内 attempts/rescued/failed 计数，额外推理会话按需创建、闲置 180 秒释放 | 不等于已有长期、逐词、可判断对错的统计系统；64 个名额也不是 64 个常驻模型 |
| 当前没有从采样到批量训练、验收和救援退役的产品闭环 | 本方案新增的是这个闭环，不把现有保存样本描述成自动训练 |

本地先前的 [Codex 实录小试](专业词识别复测与处理建议-2026-10-23.md) 已给出有限证据：第二轮三次训练读音从 0/3 到 3/3；同一原录音中未参与梯度训练的开发读音从 0/3 到 2/3。同时一条原本正确的英文出现新错误。该实验未上线，开发片段不是独立新录音，也未导出 INT8。结论是「能学习，泛化和副作用仍待验证」。

## 3. 日常如何录入：以少操作为核心

### A. 首选：日常听写自动留档，空闲时人工筛选

用户开启「保存听写记录」后，只保存 VoxFix 正在听写时收到的音频和识别记录，暂停听写即停止采集，不持续监听日常环境。采集、入选训练和启用新模型是独立动作；本轮讨论不等于立即开启采集。

每段自动留档，不要求当场点保存或纠正。按录音轮次和真实识别分段组织历史，保留边界、片段顺序及必要上下文；「一句」不能只靠句号切音频，避免单词被切断、漏掉尾音或音文错配。

记录至少区分：音频、首次向用户显示的草稿、最终显示文本、救援及替换之前的裸识别、用户后来编辑的训练标签、模型版本与时间。草稿会修订，不能用最终文本覆盖首次显示结果；不必为每次细小草稿变化存一份音频。「我没改之前的文本」在历史里保持可查看，训练标签初始可预填最终显示文本，并明确标为「未核对」。

用户空闲时打开词典内的「听写记录」：按日期浏览 → 点播放试听 → 在预填文本上修改 → 勾选「用于训练」。文字一开始就对的好样本也允许勾选，不必先制造错误。其他记录可以暂留、忽略或删除；不进入实时词典、不占救援池。

修改文本只是编辑标签，勾选才代表入选训练。即使用户改过、系统排在高优先级，未亲自勾选的记录也不得自动用于训练。批次启动前列出选中的条数、时长及排除原因，允许撤选。入选但音频损坏或明显音文不匹配时拦下并说明，不私自改标签或补选其他材料。

第一版不读取所有应用的编辑内容，也不假定能可靠追踪跨应用修改。在聊天框改字可能是在重写意思，并不证明 ASR 错误；应用内修订草稿更不是用户纠错。历史页的试听、标签编辑和明确勾选就能独立完成闭环。

示例，以下错法仅用于演示，不能自动加入真实词典：

| 项目 | 内容 |
|---|---|
| 原声音 | 本人实际说的「用 Codex 帮我检查这个函数」 |
| 保留的原始识别记录 | 用 coldex 帮我检查这个函数 |
| 用户确认的完整文字 | 用 Codex 帮我检查这个函数 |
| 用户选择 | 勾选「用于训练」后进入候选批次；仅改字不自动入选 |

一段音频必须对应它实际说出的完整文字。如果音频中说了整句，只填 `Codex` 会造成错误训练标签。只改输出中错的部分，保留实际说出的其他词、重复和停顿词；不能顺便删掉口头语、润色或补写没说的内容。若想训练更简洁的一句，应按简洁文本重新录音。

原音必须在当时保留，不能从识别文字还原。未开启记录、文件缺失或已经删除的历史只能补录，标记「补录」。音频与索引沿用本地私有、唯一 ID、完整落盘再提交元数据的规则，不能把听写原音或文本提交 Git、上传云端。

保存功能须显示开关状态、占用空间和保存失败。16kHz 单声道 PCM16 原音每小时约 115 MB（约 110 MiB），指实际保存音频的时长，不是电脑开机时长。设置可见的容量上限；到上限先提示并暂停新增留档，普通听写继续，不能静默删掉未审核材料或已选样本。具体保留天数与清理方式待实现时确定，不把本方案当作删除授权。

历史状态采用「未核对 / 已核对 / 已选训练 / 已忽略 / 已归档」，与下文的问题解决进度分开；参加过某轮训练不代表该词已经学会。已有 `VoiceSample.state: collected` 保持不变，通过独立历史/批次记录表达审核和选择。

### B. 主动录入：按正确内容说

在现有「录音纠音」页填写正确词或完整句子，录音、试听、确认保存。保存到采集档案，仍需明确勾选才入选训练；不自动新增文字替换、不自动占救援名额。

用户只读正确目标内容，用平时的口音和语速；不必读出「错误词、正确词」这一对。错词只是定位问题的线索，监督训练的核心是声音和准确文字。误读了提示句，就重录或把文字改成实际内容，不能继续沿用提示句标签。

### C. 批量人工补课：系统给短句，用户依次读

系统按本人确认过的高频错误准备一小组卡片：显示完整正确句子 → 录音 → 自动停止或手动停止 → 试听确认 → 下一句。自动停止必须可重录，保留尾音；一次集中完成少量卡片，不弹出多轮复杂设置。

例如重点练 Codex，给出以下不同语境：

1. Codex。
2. 打开 Codex。
3. 用 Codex 帮我检查这个函数。
4. 今天先不用 Codex，先跑测试。
5. Please open Codex.（本人确实会这样混说或说英文时才录。）

同时补录未包含目标词的普通句、否定句和易混词反例，避免模型学成「听到类似声音就补 Codex」。`cache / cash` 这类同音词主要依赖上下文；个人发音再稳定，也无法仅凭同一声音保证判断词义。

AI 可以建议补录清单；没有原音、本人确认或明确上下文时，所谓「明显错误」只能进入待确认，不能直接变成训练真值。真实错误优先；假设的错法不得混成已发生的错误。对用户已确认的个人英文纠正偏好继续尊重，不因错法也是合法英文就擅自删除。

## 4. 第一批录多少，怎样避免只背课文

以下是工程试验起点，不是官方最低样本量，也不是效果承诺：

- 先选最常错的 5–10 个词或短语；每项收集约 10–20 段不同表达，单段通常 3–10 秒，独念词可以更短。
- 分不同日期或会话，用日常麦克风、自然声音录制；覆盖正常语速、连读和真实常用句。不要刻意模仿播音腔，也不要把十遍完全相同的朗读当成十种场景。
- 第一轮可从约 15–30 分钟已确认的个人音频开始做隔离可行性试验，其中包含自然表达与普通句；不足时先采集，不凑数、不承诺够用。
- 单词录音帮助针对术语，短句和自然纠错帮助学习连读、上下文与语气，两者都需要。与首遍已正确的普通个人录音混合，避免训练材料只有错误词。
- 预先划分训练、开发和验收，参考 70% / 15% / 15%；实际先保证每个重点词有独立新录音，比例其次。按录制会话和原录音分组，并去除重复/近重复句；同一录音的切片、变速或加噪版本必须在同一组。
- 个人适配的验收说话人仍是本人；重点隔离的是日期、会话、原音和句子模板，不是把本人整体留出。最终验收使用另一会话的新表达，不能只换日期复读训练原句。

验收材料不参与梯度训练、挑检查点或反复调参数。用来分析并继续改模型后，该批材料转为开发集，再录新的验收材料；不重复利用既有最终封存集挑配方。

## 5. 技术路线与批量训练

| 路线 | 学到什么 | 本项目建议 |
|---|---|---|
| 文字替换、解码期热词救援 | 指定词的即时纠正或偏置，不学习本人发音 | 继续作为临时兜底，和训练材料分开 |
| SenseVoice 监督微调 | 本人语音到文字的对应、个人发音与常用表达 | 首选；官方已有微调入口，本地已有 R5 训练先例 [S1] |
| 只更新部分参数、LoRA / Adapter | 尝试以较少训练参数完成适配 | 部分参数更新可作为试验；官方尚无完整的 SenseVoiceSmall LoRA 配方，不能把其他 ASR 的开关当作现成功能，导出及 INT8 也需验证 [S3][S4] |
| 识别后再用语言模型润色 | 根据文本猜正确表达 | 不能直接解决声学口音适配，第一版不增加这一层 |

推荐从已核验的 R5 浮点 PyTorch 检查点生成隔离的个人候选；不是直接训练生产 INT8 ONNX。复用本地训练环境与现有导出路径，小学习率、有限训练、保留基线；用开发集决定停止，不照搬官方通用示例的轮数。

个人数据与许可允许使用的通用中文、英文、中英混说训练材料混合回放，同时保留过去已学会的个人训练材料。混合比例和更新哪些参数需小规模开发比较，不预先声称某个比例最优。不能只对新错词连续加训，以免旧词和普通英文逐批退化。

第一次从 R5 出发；后续保持 R5 锚点和每批版本/数据清单，比较当前个人版本及候选，避免无法追溯地叠加。若采用已有个人版本继续训练，也必须混入以往训练材料，不能把新一批当成唯一教材。

训练可以按用户选择的空闲时段手动批量启动；先做手动批次，不后台偷偷训练。训练放在隔离工作进程，不阻塞日常听写；训练用 GPU、日常继续 CPU 识别这一部署方式需以机器实际显存和运行负载验证。当前不估算训练完成时间，不承诺日用电脑一定可并行无影响；移动盘空间依旧按既有约定，实际使用前确认。

候选训练结束后导出 ONNX、量化 INT8，重测最终交付文件。目标是把改善留在首遍同结构模型里，从而不要求日常额外加载一个个人推理模型；实际内存、首字延迟和速度仍须测量。

## 6. 救援池怎样退出，记录怎样不再反复出现

先分开三件事：训练档案、文字纠正规则、参与近音救援的词。一个训练档案可以对应多个易混词或整句，也可以完全不参与实时救援。

当前窗口把所有词写入 `hotwords`，因此只在列表上标「已训练」是不够的：下次保存会重新加回救援池。实施时需要显式保存每词是否参与救援，并同步编辑器读取、保存、计数、预览/测试夹具；旧文件迁移保持原启用状态和规则 `context`，不静默停用现有词。

推荐问题状态：

`待补录 → 待批次 → 训练中 → 待验证 → 观察中 → 已归档`

失败则回到待补录或待批次，并显示原因；「该录音已被某批次使用」只是使用记录，不代表对应词已经稳定。独立批次清单记录样本 ID、训练/开发/验收分组、标注版本和模型版本，原始采样 `state: collected` 不变。

某词退出救援的建议条件：

1. 候选 INT8 在独立新录音、关闭该词救援和替换的条件下稳定输出正确词，覆盖自然句、独念和本人实际使用语言场景。
2. 检查本人其他词、普通中英文、混说、否定和近音反例，没有不可接受的新回归。
3. 先停用该词近音救援，保留其他必要兜底；再单独验证是否也可停用其文字替换。不把两类开关视作同一项。
4. 本人完成一段真实使用观察后归档；出现已确认复发可一键恢复该词兜底并收集新例。

第一版可用「每词至少 20 段跨会话新例、覆盖多种语境且无目标词错误」作为允许进入观察的保守起点。这不是证明错误率为零，小样本通过仍需本人日常验收；未覆盖的词、语言或语境保持待验证。

归档从待办列表默认隐藏，保留查询、恢复和模型回滚。回滚模型时，同时恢复与旧模型对应的救援启用清单和规则启用状态；原音和个人文字内容不回退覆盖，外部已改词典要比较后合并，不能拿旧快照覆盖用户后续编辑。

## 7. 平时统计什么

建议本地按词/问题聚合以下计数，并关联产生该结果的模型版本：

| 统计 | 用处与限制 |
|---|---|
| 本人确认的错误次数、最后发生时间、未处理样本数 | 决定优先补录什么；确认过的纠错才是真实错误 |
| 救援触发、被采纳次数，文字替换命中次数 | 反映兜底使用情况；命中或采纳不保证改对 |
| 有准确标签的独立录音中，关闭兜底时的正确/错误次数 | 判断模型是否学会；必须有实际出现次数这个分母 |
| 新增回归、恢复兜底次数 | 阻止「总分提高但关键词变坏」被忽略 |

不把「最近没触发」等同于学会：可能根本没说该词，也可能错得太远没触发门禁。即使现在词典输出正确，也不能据此证明裸模型正确。

审核推荐顺序：本人多次确认的重复错误 → 首次与最终结果差异较大的片段（只是线索，不当作已证实错误）→ 稀缺词/新语境 → 已选内容的近重复。录音质量良好、标签完整的优先；削波、截断、多个人同时说话的提示人工检查。严重错句也可用，只要原音清楚且能补齐准确全文。排序只改变展示，不代替用户勾选，也不自动生成正确答案。保留少量已正确的普通句作为候选，避免只推荐错词。

优先采用已保存样本离线回放，不在日常每句话旁边额外跑一个影子模型。未保存原音的段落不能补做声学对照。开启听写记录后按第 3 节保存音频和各阶段文字；关闭时不新增持久原音/文本档案。不记录其他应用整段内容。

## 8. 验收、实施顺序和边界

### 第一阶段：采样不再挤救援池

复用现有文字/录音双页，增加「仅收集训练材料」能力，支持完整句子与多段录音，显式保存救援启用状态。训练待办与实时词典分离。优先支持填正确文字后批量朗读，不先做复杂的跨应用修改监听。

### 第二阶段：日常快速纠错和批次准备

新增用户开启的持久听写记录、试听改字、明确勾选和审核推荐排序，以及确认错误统计；生成短句补录队列。建立私有、可复现、不会重复分组的批次清单，显示材料质量及缺少哪些独立验证样本。已冻结批次保留标签快照和来源，后续改字或撤选不得悄悄改变该批次，须重建待训练批次。以前使用过的个人材料，仅在用户选择允许保留其训练资格时作为回放；未勾选的新历史不能借「通用回放」进入训练。

### 第三阶段：一次真正的个人微调试验

先选 5–10 个本人常错目标，使用隔离候选和全新验收录音。报告修复、未修复、新变坏逐条差异，以及中文按字、英文按词、中英混说和目标词分项。比较至少三组：当前 R5 关闭兜底、个人候选关闭兜底、当前实际生产配置；最后验证候选配剩余兜底的组合。

必须按生产 VAD 分段、草稿/定稿和最终 INT8 路径回放，不能只以整段 PyTorch 解码成绩决定上线。检查静音误插词、否定、截断尾音和相似词误替换，以及模型内存和首字延迟。通过固定音频协议、启动与送字验证后，还需本人自然麦克风体验。

### 第四阶段：逐词退役与归档

只对证据充分的词进入观察，不清空整个救援池。启用前保留当前模型和对应配置；模型文件、资产哈希、版本记录与回滚路径一并维护。失败保留材料和报告，日用继续原模型。

涉及窗口和采样的实现按仓库约定运行离屏 `--dictionary-test`、往返 JSON 校验、真实 `--dictionary-capture-test`；救援开关/序列化改动运行 `test_dictionary.py`、`test_hotwords.py`，识别统计接线运行协议及语言守卫测试。原生测试真实桌面串行运行。本次仅写方案，未运行这些产品测试。

## 9. 一手资料与证据边界

- [S1：SenseVoice 官方微调脚本](https://github.com/QwenAudio/SenseVoice/blob/main/finetune.sh)：提供独立训练/验证数据、训练器与模型输出入口，证明同架构监督微调路线存在；不是个人小样本效果或推荐轮数的保证。
- [S2：Learning to Adapt: A Meta-learning Approach for Speaker Adaptation，Interspeech 2018](https://www.isca-archive.org/interspeech_2018/klejch18_interspeech.html)：研究说话人适配，并明确适配权重和更新安排影响过拟合。模型与方法不同，不能移植其结果作为 SenseVoice 本人效果。
- [S3：Updating Only Encoders Prevents Catastrophic Forgetting of End-to-End ASR Models，Interspeech 2022](https://www.isca-archive.org/interspeech_2022/takashima22_interspeech.html)：在所研究的模型与跨域任务上，限制编码器部分参数更新有助于减少遗忘；支持比较受限更新策略，不证明 SenseVoice 仅训编码器就一定安全。
- [S4：FunASR 官方 SenseVoiceSmall 持续微调指南](https://github.com/modelscope/FunASR/blob/main/examples/industrial_data_pretraining/sense_voice/CONTINUAL_FINETUNING.md)：讨论口音、方言和领域适配，强调保留旧能力的分项验收、回放与受限更新；第 6 节说明尚无完整文档化 LoRA 配方。其通用跨域验收要求说话人隔离，本项目个人适配则另用本人跨会话验收，通用能力集仍保持说话人隔离。
- [S5：Personalizing ASR for Dysarthric and Accented Speech with Limited Data，2019](https://arxiv.org/abs/1907.13511)：Google 作者的实验支持少量个人数据微调可以改善特定口音和非标准发音，部分层更新也可能优于全参。论文中的分钟数和收益不能当作 VoxFix 的样本门槛或效果保证。
- [S6：Google 自然对话与朗读识别研究，2024](https://research.google/pubs/automatic-speech-recognition-of-conversational-speech-in-individuals-with-disordered-speech/)：在 27 名有言语障碍的参与者中，朗读与对话表现有明显差异，加入对话训练材料有帮助。本方案据此建议自然纠错与引导朗读并存；研究人群与本项目不同，不能直接外推收益。
- [S7：Google Assistant 个性化语音识别说明](https://support.google.com/assistant/answer/12628148?hl=en)：已有结合本机音频、识别文字和用户纠正来适应个人说话风格的产品机制。官方说明限定其 Pixel 7 / 7 Pro Assistant 功能，仅作类似工作流的参考，不能认为 VoxFix 已有同样实现或收益。
- 本地证据：[R5 启用与回滚](R5模型启用-2026-10-23.md)、[专业词实录及个人小试](专业词识别复测与处理建议-2026-10-23.md)、[已有录音采样实现](词典录音样本与紧凑布局-2026-10-23.md)。本方案样本数量、比例、工作流和退役起点均为工程建议，不伪装成论文或官方产品承诺。
