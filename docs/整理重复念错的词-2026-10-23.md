# 整理：把反复念错的同一个词收成一个

- 版本：1.6.37.0
- 日期：2026-10-23
- 状态：现行
- 前置：[个人词典-编辑器入口-2026-10-23.md](个人词典-编辑器入口-2026-10-23.md)

## 为什么做

用户说一个专有名词时会反复试几遍，每一遍被听成不同的写法：

```
col death。koex。koex。colexs。cols。koex。koex。kos。koex。col death。cols。
```

这些段落指的都是 **Codex**。手动删太累，所以加一个「整理」。

## 入口

右键菜单第二项 **整理**（漏斗图标，菜单变成四项：收起 / 整理 / 词典 / ─ / 退出）。

- 取**剪贴板文本**；剪贴板为空时取未上屏缓存。
- 整理结果**写回剪贴板**并亮起「已复制」，接着粘贴即可；来源是缓存时，缓存也一起更新。
- 录音或转写进行中不执行（避免和识别进程抢消息），只提示一句。

## 算法（不假设标点格式）

用户明确要求"要通用的，不一定都是这个格式"，所以不做"按句号切段"这种实现：

1. **切 token**：从左到右扫描，每个位置先试**词表最长匹配**（所以 `col death` 是一个 token，不是两个），
   没命中就取一个拉丁词（字母/数字/`'-`）或一串中文。
2. **分隔符分级**：`。！？；!?;` 是硬分隔，空格/逗号/顿号/换行是软分隔；合并后按同类还原，
   不会把"把 Codex 的配置发我"拼成"把。Codex。的配置发我"。
3. **相邻合并**：相邻 token 相似就只留一个 —— 完全相同（不分大小写）、**辅音骨架相同**
   （`koex`/`kos` 这类元音乱写的会撞上）、或编辑距离 ≤1（≤5 字母）/≤2（更长）。
   两个都来自词表时保留先出现的；一个来自词表时保留词表那个。
4. 结果连接：硬分隔还原成 `。`（中文）或 `. `（纯英文），软分隔在有拉丁词的一侧还原成空格。

所以下面三种写法结果一致：

| 输入 | 输出 |
|---|---|
| `col death。koex。koex。colexs。cols。kos。` | `Codex` |
| `col death koex koex colexs cols kos` | `Codex` |
| `koex,koex,koex` / `koex   koex   koex` | `Codex` |

而正常句子不受影响：

| 输入 | 输出 |
|---|---|
| `把 col death 的配置发我。koex 装好了吗。` | `把 Codex 的配置发我。Codex 装好了吗` |
| `今天天气很好。今天天气很好。` | `今天天气很好`（去掉重复句） |
| `这个 api 返回 json 数据。api 又错了。` | 原样（`api`/`json` 不在规则里，只按相似度去重） |

## 边界（重要）

**只有词表能给出"哪个写法是对的"。** 整理不会凭空猜到 `Codex`：它靠 `dictionary.json` 里
`{"to": "Codex", "from": ["col death", "koex", "colexs", "cols", "kos", ...]}` 把这些写法归到一个正词，
然后重复项才收成一条。所以流程永远是：**先往词典里加一次，之后按「整理」就自动收成一个**。
不在词表里的变体只会按相似度去重，保留先出现的那个写法。

整理是手动动作，因此 `context: "zh"` 的规则在纯英文文本上也会生效（实时听写时不会）。
