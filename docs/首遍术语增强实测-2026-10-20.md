# 首遍术语增强：本轮未通过替换门槛

用户目标：中文、中英混说尽量在第一次输出时识别正确，不以明显增加出字等待或大量后期回改为代价。

结论：已验证两条 Nemotron 术语增强路径，并加测已有中文流式 Zipformer。当前没有候选同时优于日用版本的准确率与出字表现，因此**未修改 app、未替换程序或识别默认配置**。日用版本仍为 1.3.1、transcribe.cpp 0.4.0、Nemotron Q8_0、CPU 4 线程。错字问题尚未解决。

## 验证过的路径

1. **官方 NeMo-Speech.cpp 0.2.0 + 当前官方 GGUF**：成功加载、CPU 流式推理、请求级词语增强、全零静音和关闭。新的官方文件为 742090464 字节，SHA-256 `3fc991d3badad7277c11030a7519832cddaf2057aafed6d4b25147e953a070b1`，存放于 `models/nemo-official`。它与此前无法加载的 751094240 字节社区 GGUF 格式不同。适配器：`tools/nemo_context_probe.py`。
2. **sherpa-onnx 源码构建**：PyPI 当前最新 1.13.8 实测拒绝 NeMo `modified_beam_search`；上游提交 `51aaac5a46f78c341e4c6a6d090fcd3687c65fc2` 已包含这项支持。锁定此提交，Windows Release / CPU / Python 3.13 构建成功，位于 `runtime/sherpa-context-51aaac5`，未写入当前 Python 环境。为使官方 HF BPE 的准确词元直接进入 ContextGraph，实验构建在 `utils.cc` 添加 `modeling_unit=tokens` 分支，仍走原有词元存在性校验；未修改打分算法。此包只导出所需的 OnlineRecognizer，不是通用 sherpa 安装包。[上游源码](https://github.com/k2-fsa/sherpa-onnx/blob/51aaac5a46f78c341e4c6a6d090fcd3687c65fc2/sherpa-onnx/csrc/online-recognizer-transducer-nemo-impl.h)
3. **Zipformer 流式对照**：复用已有公开模型文件，测试多候选解码与术语增强，未接触手机或私人词典。

术语表统一使用 VoxFix、Blender、GLM、Kimi、GPT、Qwen、Python、GitHub、WiFi、PDF、API、JSON、git status、git commit；没有针对某句错误写替换规则。Nemotron 分词使用官方 `tokenizer.json`，逐项核验编码非空、没有未知词元、解码能还原术语，再映射为 ONNX 的词元文本。

## 文字稳定与真实节奏

原始 beam 输出会改写前缀：64 条初测中 10 条触发生产前缀保护，不能直接用于当前只追加的输入方式。实验增加“最近三次真正解码的共同前缀、英文词尾不提前提交”，补充延迟提交、前缀回退拒绝的自检；稳定后的 64 条各组协议错误为零。它只延后提交，没有回删已输入文字。

全部构建与批量测试结束后，每 100ms 按音频墙钟投递，包含真实解码耗时：

| 配置 | 普通句首字 | 13 秒长句首字 | 新 Blender 句首字 |
| --- | ---: | ---: | ---: |
| 当前日用版本 | 1200ms | 1178ms | 1192ms |
| 官方右上下文 6、增强 2 | 1148ms | 761ms | 763ms |
| 新 sherpa 稳定 beam、增强 1.5 | 1140ms | 1043ms | 1140ms |

官方运行时还有最终标点/大小写改写，例如实时 `今天天气很好, ...` 到 final 去掉逗号，或 Blender 到 blender。这会触发现有目标框前缀保护；即便将格式变更另外解决，表中的识别准确率也没有达到替换门槛。稳定 beam 避免了这三条的 final 前缀变化，但正确率没有提升。

真实节奏结果：`work/context-20261020/final-paced.json`。复现：`tools/context_latency_check.py`。这些延迟不包括真实麦克风驱动或跨应用绘制，因此不是用户开口到屏幕的完整延迟保证。

## 本轮交付与剩余问题

- 保存了可复查的模型、锁定版本的实验运行时、协议适配器、预分词热词、自检与对比结果。没有安装大语言模型作为必经纠错步骤，没有改动桌面交互、系统音量或设备策略。
- 当前程序、已有用户输入与未输入文字丢弃行为保持原样；没有生成 `work/未输入的文字.txt`。
- 本轮同模型热词增强和现有中文流式对照均未满足“整体更准且不拖慢”的目标，不能发布为准确率升级。
- 下一步需要这段实际错误转写对应的原始音频与可核对原文，才能确定是拾音、口音、英文读法还是模型本身的主要限制，继续筛选更强首遍模型。不能仅凭错误转写猜测模型名和版本号，也不能以这组测试证明所有候选都不行。

后续已收到对应原视频并完成复测，见 [原视频识别复测](原视频识别复测-2026-10-20.md)。原音轨仍复现大量错误，不能将此前错字归因于外放拾音；新版 beam 在真实视频上也出现确认前缀变化，因此不能把合成语料的稳定性结论外推到日常使用。
